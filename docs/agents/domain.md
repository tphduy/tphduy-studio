# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` at the root and ADRs under `docs/adr/`.

## Before exploring

Read the root glossary and ADRs relevant to the area being investigated.

If these files are absent, proceed silently. The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issues, proposals, hypotheses, and tests. Reconsider unfamiliar terminology or record a genuine gap for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR, and explain why the decision should be reconsidered.
